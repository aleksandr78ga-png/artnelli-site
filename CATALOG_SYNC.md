# Синхронизация каталога

Настройка 6 октября 2026 по поручению Нелли: восстановить синхронизацию сайта,
Telegram Mini App и MAX с группой «Купальники в наличии».

## Неизменное правило каталога — поручение Нелли от 6 октября 2026

Единственный первичный источник товарных карточек — Telegram-каталог
`nelli_leotards`, группа «Купальники в наличии», чат `-1001871308468`.
Сайт, приложения и магазины получают данные из этого источника через общий
каталог. Независимые ручные копии не допускаются.

Обязательно автоматически синхронизировать **добавления, подтверждённые удаления
и все редактирования**: название, описание, цены и валюты, размеры и мерки,
состояние, категории, продажу/аренду, варианты, фотографии и ссылки.
Удалённая публикация должна исчезнуть из товарной витрины, а не оставаться
карточкой «Продан» или в публичном архиве.

Правило действует для artnelli.com, Telegram Mini App, MAX и всех будущих
витрин, сайтов, приложений, каналов с товарными карточками и магазинов,
включая VK и Avito. Уточнённое Нелли расписание:
- **Каждый час** проверять и автоматически синхронизировать добавления и
  подтверждённые удаления карточек.
- **Раз в сутки** полностью сверять и автоматически синхронизировать
  редактирования всех товарных данных и фотографий.

Обе проверки обязаны проверять фактическую доставку на все подключённые
витрины. Существующий быстрый путь событий бота сохраняется; плановые проверки
восстанавливают пропущенные события, а не только сравнивают число карточек.

Использовать постоянные ID Telegram и подтверждённые ID сообщений альбома.
Название не является идентификатором. Продажу, аренду и разные варианты
не объединять произвольно. Цену «по запросу» не заменять нулём или выдуманной
суммой. Неполный экспорт, ошибка или потеря входа не доказывают удаление.

Это **постоянное поручение и разрешение Нелли на штатную автоматическую
синхронизацию**. Отдельное подтверждение для каждого добавления, изменения
или подтверждённого удаления карточки не требуется. Оно не разрешает новые
платные подписки, предоставление дополнительных прав или изменение первичного
источника без явной команды Нелли.

Новую витрину подключать к общему каталогу. Перед объявлением синхронизации
работающей проверить автоматические создание, редактирование и удаление,
сохранение ID и отсутствие дублей. Подготовленный файл выгрузки не означает,
что магазин автоматически его принимает. Ограничения представления полей
площадки описывать явно, сохраняя исходный смысл и все доступные характеристики.

При сбое сохранять последние подтверждённые данные, повторять операцию и
сообщать Нелли о блокировке или превышении суток без успешной полной сверки.
Не выставлять успешную сверку после частичного чтения или без проверки
опубликованного результата. Техническая процедура — в `CATALOG_SYNC.md`.

## Действующий путь данных

- Существующий Telegram-бот принимает публикации и правки через защищённый webhook.
- Общий загрузчик `site/api/live-data.js` читает публичный серверный `/api/catalog`
  при открытии витрины, возвращении в неё и каждую минуту, пока она видима.
- Этот endpoint читает сохранённые события, не ждёт полного обхода Telegram.
  При недоступности сервера витрины сохраняют последний пригодный каталог.
- GitHub продолжает публиковать статическую резервную копию по прежнему расписанию;
  задержки GitHub больше не задерживают доставку полученных ботом событий в витрины.
- Существующие альбомы используют сохранённые изображения artnelli.com. Истёкшие
  публичные CDN-ссылки не заменяют их. Позднейшие фактические правки фото принимаются
  отдельно от правок подписи, через файловые идентификаторы бота.

## Удаления и полнота истории

Bot API не сообщает об обычном удалении сообщения. Публичная страница форума может
быть недоступна. Поэтому отсутствие нельзя выводить из ошибки, пустой страницы,
экрана входа, одной карточки или неполного списка.

Ежечасная задача «Добавления и удаления Telegram» читает всю группу, все товарные темы
и отдельно тему «Аренда» 1865 через авторизованный Telegram Web. Читать только
эту группу; не открывать личные переписки, служебные коды, cookies или хранилище
авторизации. При отсутствии входа сообщить о блокировке, не менять подтверждения.

Для всей группы создать фактическое наблюдение с:

```json
{"channel":"nelli_leotards","source":"authenticated-telegram-catalog",
 "scope":"all-product-topics","checkedAt":"текущее ISO-время",
 "complete":true,"reachedStart":true,"reachedEnd":true,
 "allProductTopicsRead":true,"albums":[]}
```

В `albums` записать реально прочитанные сообщения и ID фотографий по правилам
ниже. Альбом считать одним объявлением. Собирать ID на каждом шаге прокрутки
при виртуализации. Флаги полноты выставлять только после
достижения обеих границ каждой товарной темы без пропусков загрузки.

На свежей main выполнить `node scripts/record-catalog-history.mjs OBSERVATION.json`.
Перед чтением загрузить также `scripts/catalog-observation.mjs`. ID карточки
сайта может принадлежать отдельной фотографии альбома, а не его видимому корню.
Для каждого `.Message[data-message-id]` собирать `rootId`, реальный `mainId`
из `.bottom-marker[data-album-main-id]` и все фактически видимые ID элементов
`[id^="album-media-message-"]`. Не выводить отсутствующие ID из числового диапазона.
На каждом шаге объединять наблюдённые ID одного альбома; при виртуализации
сохранять предыдущие шаги. Не читать внутреннее состояние Telegram, cookies
или React/Redux. Цитаты ответов отделять от собственного текста сообщения.

В наблюдение передавать `albums: [{rootId,mainId,memberIds,isAlbum,isReply,
ownText,topicId}]`. Скрипт сам сопоставит физические сообщения с опубликованными
карточками и ранее подтверждённой привязкой альбомов. Например, «Изумруд»
5461 находится в альбоме с корнем 5455; такое различие не является удалением.
Ответ со снижением цены не является отдельным товаром. Сохранять отдельные
предложения продажи и аренды одной модели.

Для отдельно полностью прочитанной аренды также следовать `RENTAL_SYNC.md` и
`scripts/record-rental-history.mjs`. Два полных чтения с интервалом минимум десять
минут подтверждают отсутствие. Прочитанный снова пост сбрасывает отсутствие.

Для подтверждения удалений опубликовать только фактически изменённые
`data/telegram-catalog-history.json` и `data/telegram-rental-history.json`,
обычным коммитом в main с проверкой HEAD, без force push. Не редактировать
счётчики вручную. Правки остальных полей выполнять по процедуре полной сверки ниже. Сервер перечитывает подтверждения
раз в пять минут; публикация резервного каталога также применяет эти удаления.

Проверять итоговый `/api/catalog` и опубликованный каталог. Уведомлять Нелли только
о реальных изменениях или необходимости восстановить вход. Полнота истории и
обнаружение обычных удалений зависят от действующего входа в Telegram Web.

Цены в рублях распознаются и в записи «38 тысяч рублей». Проверка резервного
издателя использует те же правила; суммы в долларах в рублёвую цену не переносятся.

## Полная сверка добавлений и редактирований

Ежедневная задача «Правки карточек Telegram» полностью проверяет содержание
всех действующих объявлений, даже если события бота не показывают изменений.
Ежечасная задача «Добавления и удаления Telegram» проверяет появление и
подтверждённое исчезновение объявлений. Обе задачи включены; первичный
источник, общий каталог и издатель site.yml остаются едиными.

Расписание в часовом поясе Asia/Yekaterinburg:
- добавления/удаления — каждый час, в 52-ю минуту;
- правки карточек — ежедневно в 13:22, первый запуск 6 октября 2026.

Первый запуск по обновлённым заданиям должен подтвердить фактическое исполнение;
сохранённая настройка сама по себе не является успешным проходом.

1. Прочитать все товарные темы через действующий авторизованный Telegram Web.
   Собирать собственную подпись без цитат, зачёркнутых старых цен и служебных
   сообщений; отдельно фиксировать фактическую связь ответов о цене с исходным
   объявлением. Не переносить цену по совпадению названия.
2. Сопоставить полный набор объявлений по постоянным ID и подтверждённым
   связям альбомов с общим каталогом и опубликованной резервной копией.
   Проверить название, описание, цену/валюту или «по запросу», размер/мерки,
   состояние, продажу/аренду, категорию, варианты, ссылки, количество,
   состав и порядок фотографий. Различия формата и перевода допустимы,
   различия товарных фактов — нет.
3. Не считать временную CDN-ссылку изменением фотографии. Сверять фактическое
   изображение/файловую идентичность и состав альбома. Не заменять пригодные
   сохранённые фото истёкшими ссылками; при подтверждённом изменении изображения
   обновить его устойчивую копию через существующий импорт.
4. При пропущенном добавлении или редактировании восстановить доставку через
   действующий бот, общий серверный импорт и существующий издатель
   `site.yml`. Проверить обработку текущего исходного текста и защиту от
   устаревших событий. Если необходима правка импортера, выполнить её,
   соответствующие проверки и публикацию в рамках постоянного поручения.
   Не исправлять три витрины отдельно и не создавать второй издатель.
5. Для удалений использовать полные наблюдения и два подтверждения по
   процедуре выше. Для редактирований одного объявления достаточно
   однозначно прочитанной текущей редакции; ошибка/частичное чтение не дают
   права подставлять пустые значения.
6. После изменений проверить общий `/api/catalog`, успешное обновление
   резервной копии и фактические карточки сайта, Telegram Mini App и MAX.
   Сверять результат по ID и значениям, а не только общему числу товаров.
   Для каждой будущей подключённой витрины также проверять её приём данных.
7. Сохранять компактный результат успешной полной сверки с реальным временем,
   охватом тем, сопоставленными ID и изменениями; не публиковать сырые
   переписки, коды входа или данные сессии. При блокировке/сбое повторить
   операцию и уведомить Нелли; не отмечать полный успех.

## Подключение будущих магазинов

VK сейчас имеет подготовленный исходящий экспорт; рабочий принимающий
адаптер не подтверждён. Следовать `VK_SYNC.md`: сохранить существующие
карточки и их привязки, проверить обновления и удаления, отдельно разрешить
представление цены по запросу и вариантов. Отсутствие в частичном YML не
означает удаление из Telegram.

Avito — планируемая витрина; действующее подключение не подтверждено.
Для VK, Avito и любой новой площадки применить это же правило до запуска:
единый источник, постоянные ID, автоматические добавления/правки/удаления,
полная сверка не реже раза в сутки и проверенный результат приёма.
Не объявлять будущую интеграцию работающей до фактической проверки.
