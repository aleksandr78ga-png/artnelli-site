# Синхронизация каталога

Настройка 6 октября 2026 по поручению Нелли: восстановить синхронизацию сайта,
Telegram Mini App и MAX с группой «Купальники в наличии».

## Действующий путь данных

- Существующий Telegram-бот принимает публикации и правки через защищённый webhook.
- Общий загрузчик `site/api/live-data.js` читает публичный серверный `/api/catalog`
  при открытии витрины, возвращении в неё и каждую минуту, пока она видима.
- Этот endpoint читает сохранённые события, не ждёт полного обхода Telegram.
  При недоступности сервера витрины сохраняют последний пригодный каталог.
- GitHub продолжает публиковать статическую резервную копию по прежнему расписанию;
  задержки GitHub больше не задерживают доставку полученных ботом событий в витрины.
- Существующие альбомы используют сохранённые изображения artnelli.com. Истёкшие
  публичные CDN-ссылки не заменяют их. Позднейшие фактические правки фото принимаются
  отдельно от правок подписи, через файловые идентификаторы бота.

## Удаления и полнота истории

Bot API не сообщает об обычном удалении сообщения. Публичная страница форума может
быть недоступна. Поэтому отсутствие нельзя выводить из ошибки, пустой страницы,
экрана входа, одной карточки или неполного списка.

Существующая ежечасная задача дополнительно читает всю группу, все товарные темы
и отдельно тему «Аренда» 1865 через авторизованный Telegram Web. Читать только
эту группу; не открывать личные переписки, служебные коды, cookies или хранилище
авторизации. При отсутствии входа сообщить о блокировке, не менять подтверждения.

Для всей группы создать фактическое наблюдение с:

```json
{"channel":"nelli_leotards","source":"authenticated-telegram-catalog",
 "scope":"all-product-topics","checkedAt":"текущее ISO-время",
 "complete":true,"reachedStart":true,"reachedEnd":true,
 "allProductTopicsRead":true,"posts":[]}
```

В `posts` записать реально прочитанные корневые ID объявлений, названия и
`telegramTopicId`, если он виден. Альбом считать одним объявлением. Собирать ID
на каждом шаге прокрутки при виртуализации. Флаги полноты выставлять только после
достижения обеих границ каждой товарной темы без пропусков загрузки.

На свежей main выполнить `node scripts/record-catalog-history.mjs OBSERVATION.json`.
Перед чтением загрузить также `scripts/catalog-observation.mjs`. ID карточки
сайта может принадлежать отдельной фотографии альбома, а не его видимому корню.
Для каждого `.Message[data-message-id]` собирать `rootId`, реальный `mainId`
из `.bottom-marker[data-album-main-id]` и все фактически видимые ID элементов
`[id^="album-media-message-"]`. Не выводить отсутствующие ID из числового диапазона.
На каждом шаге объединять наблюдённые ID одного альбома; при виртуализации
сохранять предыдущие шаги. Не читать внутреннее состояние Telegram, cookies
или React/Redux. Цитаты ответов отделять от собственного текста сообщения.

В наблюдение передавать `albums: [{rootId,mainId,memberIds,isAlbum,isReply,
ownText,topicId}]`. Скрипт сам сопоставит физические сообщения с опубликованными
карточками и ранее подтверждённой привязкой альбомов. Например, «Изумруд»
5461 находится в альбоме с корнем 5455; такое различие не является удалением.
Ответ со снижением цены не является отдельным товаром. Сохранять отдельные
предложения продажи и аренды одной модели.

Для отдельно полностью прочитанной аренды также следовать `RENTAL_SYNC.md` и
`scripts/record-rental-history.mjs`. Два полных чтения с интервалом минимум десять
минут подтверждают отсутствие. Прочитанный снова пост сбрасывает отсутствие.

Опубликовать только фактически изменённые `data/telegram-catalog-history.json`
и `data/telegram-rental-history.json`, обычным коммитом в main с проверкой HEAD,
без force push. Не редактировать счётчики вручную. Сервер перечитывает подтверждения
раз в пять минут; публикация резервного каталога также применяет эти удаления.

Проверять итоговый `/api/catalog` и опубликованный каталог. Уведомлять Нелли только
о реальных изменениях или необходимости восстановить вход. Полнота истории и
обнаружение обычных удалений зависят от действующего входа в Telegram Web.
